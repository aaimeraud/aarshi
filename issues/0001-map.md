# Carte : aarshi, outil CLI de scaffolding Next.js

## Destination

Une spec validée pour `aarshi` (convention, stack, périmètre des commandes `setup`, `add -s`, `add -p`), prête à être construite. Le code du CLI viendra ensuite, dans une carte d'implémentation séparée.

## Notes

- Domaine : scaffolding de sites Next.js multilingues (App Router), en reproduisant la structure `views/` + `sections/` + routes par langue + dictionnaires typés d'ouro-t3 (`docs/ARCHITECTURE.md`), sans son contenu.
- Stack : Rust, `clap` (commandes), `inquire` (questions interactives), binaire unique. Le projet généré reste en TypeScript.
- Langues : documentation en anglais (`README.md`) et en français (`README.fr.md`), convention en `CONVENTIONS.md` et `CONVENTIONS.fr.md`. Code et commentaires en anglais, commentaires courts et uniquement là où le comportement n'est pas évident, doc Rust `///` sur les fonctions publiques.
- Compétences à consulter : `domain-modeling` (glossaire et ADR), `writing-for-agents` (pour `AGENTS.md`, `CONVENTIONS.md`).
- Préférences standing : pas de `--yes` sur `create-next-app`, flags explicites ; télémétrie Next désactivée par projet ; `AGENTS.md` généré ; ESLint ; agent feedback et Cache Components désactivés par défaut, activables par flag.

## Decisions so far

- Nom : `aarshi`, libre sur crates.io, npm et Homebrew (vérifié). Dossier : `~/code/development/t3/aarshi`.
- Stack Rust retenue (`clap`, `inquire`, binaire unique via `cargo install` ou Homebrew). Projet généré en TypeScript.
- Création du projet : `<pm> create next-app@latest <dossier>` avec flags explicites (TypeScript, Tailwind, App Router, sans `src/`, ESLint, `AGENTS.md`, sans agent feedback, sans Cache Components). Gestionnaire via `--npm` (défaut), `--pnpm`, `--yarn`, `--bun`.
- `setup` : sans argument, demande le nom du dossier ; `setup <dossier>` ; `setup .` dans le dossier courant.
- Langues : liste initiale fr, en, es, ko, extensible par fichier de config. RTL déduit de chaque langue (ar, he, fa).
- Périmètre v1 : `setup`, `add -s <section> <page>`, `add -p <page>`. Si la page est absente pour `add -s`, erreur puis proposition de la créer (o/n).
- Composants externes : saisie libre, passée à `shadcn add`.
- Génération : templates embarqués dans le binaire.
- Mise à jour du sitemap en v1 : marqueurs de commentaire dans `app/sitemap.ts`.
- Télémétrie : `next telemetry disable` est globale à la machine ([recherche 0002](issues/0002-research-next-telemetry-local.md)). Retenu : variable `NEXT_TELEMETRY_DISABLED=1` pendant la création, puis ligne dans le `.env` du projet généré, sans toucher à la config globale ([décision 0003](issues/0003-grilling-telemetry-mechanism.md)).

## Not yet specified

- Mécanisme de mise à jour du sitemap au-delà des marqueurs de commentaire (AST ou registre de pages). Fragile en v1, à améliorer.
- Options de `add -p` au-delà de la création de page, de sections et de l'entrée sitemap. À faire émerger avec l'usage.
- Format du fichier de config des langues (TOML ou JSON, emplacement).
- Contenu exact des templates (section, vue, route, dictionnaire typé) et des premiers fichiers générés par `setup`.

## Out of scope

- Mode de mise à jour automatique d'ouro-t3 par l'outil. Ouro-t3 ne sera pas modifié par `aarshi`.
